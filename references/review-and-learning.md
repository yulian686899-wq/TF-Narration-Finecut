# 审核和复盘

## 审核分工

当前智能体交付前先检查内容保留、句首残词、字音、同步和媒体完整性。用户判断体验与标记问题，不承担逐刀找入点或筛选所有候选的工作。

审核网页和本地服务属于待开发的配套方案；当前可接收聊天中的时间范围与备注，并由当前智能体回原片处理。保存标注、当前智能体读取、修正和回读需要实际接通验证，不能因写进技能就宣称可用。

## 怎样接收问题

记录项目、成片版本、问题范围、类型、备注，以及对应源文件、源区间和稳定片段编号。用户给大致范围即可，精确切点由当前智能体找。

类型可以是漏剪的重复或卡壳、误删、切断字音、停顿或气口、衔接、音量与声音、转写文字错误、其他。转写错字与原声说错分开记录。

成片时间改变时按原片对应关系重新定位，无法可靠映射的旧标注不能直接套用。记录沿用项目已有形式，无需让用户填写技术字段。

## 怎样修正

1. 读取意见与对应成片版本，回原片核对前后文。
2. 查明是识别漏记、重录选择、边界、信息误删、节奏偏好、声音处理还是执行问题。
3. 调整切点或参数；误删时从原片恢复，保留前版。
4. 按根因检查本片可能受影响的同类位置，不无理由重剪全部内容。
5. 提供修正版与有上下文的局部前后对比，说明具体改了什么及依据。
6. 再检查受影响的内容、剪口和必要媒体指标，交用户复核。

问题状态为：待处理 → 已修正待复核 → 用户确认解决。用户仍不满意则返回待处理。当前智能体自检通过只能记为待复核；没有新反馈不视为认可。

## 经验怎样保存

每个案例记录源区间、问题版本和成片位置、最初决定及理由、用户意见或内部发现、修改后决定、验证方式、确认状态、可复用条件和适用边界。

| 类别 | 维护方式 |
|---|---|
| 已确认长期偏好 | 后续剪辑前读取本技能的怎么剪与标准；用户明确新增长期要求时更新对应段落，保留依据与适用范围。 |
| 已确认判例 | 在项目复盘中保留完整证据，确认后将可复用摘要维护到本参考文件，明确正确处理及边界。 |
| 待确认技术发现 | 记录内部识别、波形或程序检查发现及处理，保留待确认状态；不冒充用户反馈或正确判例。 |

单次修正先作为具体案例，不无条件升级为长期规则。更新遇到冲突时说明并调整，不累积相互矛盾的要求。用户确认整个方案不等于确认每个历史切点。

公开版不附带私人录音、转写和真实切点；以下是泛化的问题说明，不作为准确率或已验证切点的证据。

## 典型问题与检查方向

| 典型问题 | 检查方向 |
|---|---|
| 全文转写只出现一遍，原声实际有两次起句。 | 对可疑句首缩短核对窗口，结合原声和波形定位。 |
| 完整表达之前残留半句或短词。 | 单独检查句首残词，不统一给所有入点加留白。 |
| 预剪没有发现重复，最终文件里仍能听到。 | 检查实际交付文件，记录真实核对范围。 |
| 参考稿没有写到录音中的一个独立例子。 | 比较其信息，保留有效补充，不把参考稿当作内容上限。 |
| 识别把产品名称写成同音词。 | 校正转写与剪原声分开处理。 |

判断示例：“我现在……我现在介绍这个功能”中，第一次是失败起句；“我喜欢它，因为价格便宜”和“我喜欢它，而且响应很快”虽然开头相近，但各有信息。示例用于解释取舍，不对应某位创作者的原片。

技术检查、原意与听感、用户确认分别记录。帧数和响度达标不能证明没有漏剪、误删或切字。

## 怎样判断是否改善

有依据地更新规则后，用受影响的真实片段复核，同时包含正常强调、不同信息和必要停顿等不应删除的对照。

漏剪、误删和切断字音分别统计。只有用户实际审核覆盖的内容才能进入对应统计，未审核位置不算正确。可比较每分钟已审核成片的问题数、同类复发，以及用户要求补删或恢复的数量。

依据跨期记录判断改善，不承诺错误率自动持续下降，也不把零反馈算作零错误。
